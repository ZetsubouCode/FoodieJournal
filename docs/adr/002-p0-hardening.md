# ADR 002 — P0 hardening before creative work

Accepted 9 November 2026 (Asia/Jakarta), by the owner's seven P0-H decisions. Baseline: local `main` at `5ca68464f17af5e8ea330a5bcfe3bd98760ba10d`, clean working tree. This supersedes conflicting current summaries; earlier QA remains dated evidence.

| Choice | Maintained decision / rationale |
| --- | --- |
| 1B — Adaptive editorial width | Keep responsive gutters and alignment; raise the public visual shell cap from 112rem to 152rem. At 2560px this uses 2432px with 64px gutters. At 3440px the same cap deliberately bounds photographic enlargement and card groups. Explore Visit grid becomes three columns above 2000px; Food/Place four; list stays one. Reading stays 68ch, cabinet stays native 1634×963 plus tube clearance, admin stays 80rem. No photo processing size or original access change. |
| 2B+C — Place opening | Controller explicitly selects a cover independently of pagination: published-visible visits of this place, `visited_at DESC, id DESC`, same-visit cover only, ready hero derivative and file existence. Skip an unavailable newest cover for an older one. Eager-load cover/variants in batches of 50, stop at first usable cover; no query per candidate or history visit. Existing `(place_id,status,visited_at,id)` and `(media_id,variant)` indexes support selection; no migration. Without a cover use responsive title/location and genuine address/rating/rated-count/optional Maps facts, no photo column. |
| 3B — Archival atmosphere | Older cabinet-on-Explore `qa/memory-archive-v2/explore-1440.png` belongs to intermediate 801cc57 work. Retain its warm materials/local light as mood, without restoring the old shell/mechanics. Matched current views support retaining P0's public atmosphere and editorial footer; width and photo-free geometry change, palette does not. |
| 4A — Admin | Explicitly reverse the inherited/hybrid typography preserved by P0-2: modern minimal system UI fonts for body/headings, plain semantic page surface, compact footer, practical forms/lists and existing accessible primitives. Public vintage typography/background are intentionally excluded. |
| 5B — Primitives | Inventory every existing foundation and its consumers; repair demonstrated defects in shared sources. Saved success was announced as both persistent alert and transient toast: retain the alert once; async toast API remains. No component-system rewrite. |
| 6A — Skeletons | New region-matched real-wait skeletons belong exclusively to P2. P0-H verifies existing SSR/busy/empty/error/retry, retains committed data, and adds no delay or mounted skeleton. The unused generic skeleton is inventory, not a completed experience. |
| 7B — Scoped autonomy | Fix demonstrated P0 correctness defects with regression checks, including Place's out-of-range history recovery. P1 mechanics, P2 discovery/skeleton work, P3 story enhancement and P4 full access/performance work remain pending. No dependencies/schema/owner-data changes. |

Ultrawide visual review also caps discovery photos at `--curiosity-photo-max: 32rem` so captions stay in the opening viewport, and Place photography at `--place-photo-max: 50rem` so it does not overwhelm chronology. The selected Place hero's responsive variants are filtered for ready files, preventing a missing smaller derivative from replacing a usable hero with a broken image. These caps use existing compositions and preserve P0-4 pixels through 1920px.

File availability requires metadata checks until a usable candidate is found, plus the selected cover's derivative checks; this is deliberate for a small single-author archive. A pathological archive containing hundreds of missing derivatives can require several 50-row batches. Measure before introducing caching (which must invalidate publication/media eligibility) or a media-health index. Storage races after selection still use the existing runtime image fallback and media-route authorization.

[Verification, inventory, dimensions and limitations](../qa/p0-hardening/verification.md) describe the executed checks. These decisions do not certify WCAG, field performance or P1–P4 completion.
