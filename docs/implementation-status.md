## History and root cause findings

`4f6365b` is the older projector-era Explore commit, not a separately committed Memory Archive cabinet baseline. Both cabinet-on-Explore intermediate evidence and final Home migration are bundled in `801cc57`. The retained V1/V2 reports/captures are valid historical mood references; attributing all their geometry to 4f6365b would be false. No old code was restored.

The underline regression has direct evidence: `git diff 4f6365b b56db2c -- resources/css/home.css` deletes the left-origin pseudo-element transform; `git show 801cc57 -- resources/css/public-chrome.css` introduced the then-static active-only rule; P0-1 now replaces that regression. The older focused link had an outline adjustment; the new fully specified keyboard fill/re-entry contract is a requested improvement, not a falsely attributed historical behavior.

The environment still shares `.archive-page` warm surface overrides and `atmosphere.webp`. Differences arise from cascade, crop, fade and footer hierarchy, not unrelated page copies. At the audit baseline the fixed 1280px cap created 640px of unused total width at 1920px (P0-2 now uses a 1792px public shell); whether a particular void is disproportionate is judged against the requested wide layout and content, not a universal rule against whitespace.
